The problem

Every AI app becomes a new project

Each department finds its own AI tool. IT inherits the work of making them safe, connected and affordable.

  • One vendor per app. Every app brings its own contract, its own security review and its own login.
  • Usage meters that never stop. Most AI is billed by the token, so more adoption means a bigger bill that is hard to forecast.
  • Data sent out. Company documents end up in many shared services you do not control.
  • Tied to one model. Models change quickly. An app built around one vendor cannot follow.
  • Shadow AI. When the official route is slow, teams go around IT and buy their own.
Why self host

Four reasons it fits IT

You run EME once, on infrastructure you already manage. Each new app is added to it instead of being bought, reviewed and wired in again.

It fits your stack

  • Java server in a Docker container on Linux.
  • Search is embedded, so there is no extra cluster to run.
  • Pages and data are files, kept in Git.
  • Code comes from GitHub and updates from Git.
  • SSO with Microsoft, Google or OAuth 2.

Your data stays inside

  • Full data privacy on hosts you choose.
  • Your data is never mined or sold.
  • Export it, or move it to another EME Server.
  • Logins are signed with a private key.

A cost you can plan

  • 100% open source software.
  • No per token fees from EME, and unlimited tokens on your own hardware.
  • Add apps to the servers you already run.

Extend it in Java

  • Skills are Java classes that run as agent jobs.
  • Plugins are Java and HTML.
  • Open API, MCP and Websockets connect your other systems.
  • A person approves the key actions. Humans stay in control.
What you run

The stack, in plain terms

LayerWhat it is
HostLinux, with Docker. Each EME Server is self contained.
ServerJava, running in a Docker container. 100% open source.
SearchEmbedded ElasticSearch with vector search.
StoragePages and data as files, versioned in Git. Easy to back up, diff and move.
ModelsModel Connectors for hosted, local or your own models, including any model that speaks the OpenAI compatible API.
IntegrationOpen API (REST, OpenAI syntax compatible), an MCP server and client, and Websockets.
Sign inSSO with Microsoft, Google or any OAuth 2 provider. Also public and private key signatures, with login by emailed code, a registered key or an application password.
Front endsFlutter apps for iOS, Android and web.

Questions IT asks

Short answers

Where does our data live?
On your EME Server, in files and an embedded index. You choose the host. It is never harvested.
Can we run it ourselves?
Yes. It is open source Java on Linux and Docker, deployed from Git.
Do you support SSO?
Yes. Sign in with Microsoft, Google or any OAuth 2 provider.
Can we use our own models?
Yes, through Model Connectors or MCP.
What does it cost to grow?
There are no per token fees. You add the hosts you need.
What if we leave?
Export your data or move it to another EME Server.
Who approves risky actions?
A person, by design.
How do we integrate?
Open API, MCP and connectors, such as the Drupal connector used by UN News.
